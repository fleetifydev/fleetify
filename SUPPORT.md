# Getting help

Fleetify is maintained by a small team. Pick the channel that fits your question, so that the right people see it and others can find the answer later.

| You want to… | Go to |
|---|---|
| Ask a question, or get help using or building Fleetify | [Discussions → Q&A](https://github.com/fleetifydev/fleetify/discussions/categories/q-a) |
| Suggest a feature or talk through an idea | [Discussions → Ideas](https://github.com/fleetifydev/fleetify/discussions/categories/ideas), or the feature request form for a concrete proposal |
| Report a bug | [Open an issue](https://github.com/fleetifydev/fleetify/issues/new/choose) with the bug report form |
| Report a security vulnerability | [SECURITY.md](SECURITY.md): report it privately, never in a public issue |
| Report a breach of the Code of Conduct | conduct@fleetify.dev, as the [Code of Conduct](CODE_OF_CONDUCT.md) describes |
| Talk business: partnerships, press, companies | [hello@fleetify.dev](mailto:hello@fleetify.dev) |

Before you ask, search the [issues](https://github.com/fleetifydev/fleetify/issues) and the [discussions](https://github.com/fleetifydev/fleetify/discussions): your question may already have an answer. The issue forms ask for what we need to reproduce a bug, such as the version, the OS and the logs.

Please keep questions in public channels rather than writing to the maintainers directly: an answer in Discussions helps the next person too. The project's email addresses are for the private matters in the table above.

We answer as time allows. Apart from the timelines for security reports in SECURITY.md, there is no guaranteed response time.

Want to contribute? [CONTRIBUTING.md](CONTRIBUTING.md) explains how.
